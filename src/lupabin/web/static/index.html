Cómo usar el ZIP en Ghidra

Ghidra se abre fuera de esta web. El ZIP no contiene el PE ni lo importa por ti: lleva evidencias y un script para añadir anotaciones al programa abierto.

  1. Descarga «Evidencias para Ghidra (ZIP)» en «Descargar» y extrae sus dos archivos: lupabin-ghidra.json e ImportLupaBin.java.
  2. Importa el mismo PE original en un proyecto de Ghidra y ábrelo en CodeBrowser, sin ejecutarlo. Si ya lo tienes abierto, comprueba que es ese archivo.
  3. Abre Window > Script Manager. Si falta el script, añade la carpeta extraída mediante Script Directories / Bundle Manager. Busca ImportLupaBin.java en el filtro del gestor.
  4. Selecciona y ejecuta solo el script suministrado, ImportLupaBin.java, con Run Script. Cuando lo pida, elige lupabin-ghidra.json del mismo ZIP. No ejecutes el PE.
  5. Guarda la revisión previa en un archivo nuevo y lee sus anotaciones, conflictos y abstenciones. Si hay anotaciones preparadas, confirma solo si quieres aplicarlas; después guarda el programa en tu proyecto de Ghidra. Conserva el JSON y la revisión.

Si el SHA-256 no coincide, detente: no desactives esa comprobación. Necesitas el PE original completo. El ZIP del ejemplo sintético no sirve para otro ejecutable.

Usa solo exportaciones de procedencia confiable. El importador conserva las anotaciones existentes; añade evidencias, no un veredicto de seguridad. Verificar bytes no autentica el informe ni demuestra sus afirmaciones.

Preguntas de práctica sobre este informe

Cada pregunta indica con qué se responde: un hecho (una lectura de los bytes), una inferencia (el resultado de un método) o un criterio general (conocimiento de la materia, no un dato más sobre el archivo).

Un hecho es una lectura directa de los bytes del archivo; una inferencia, el resultado de aplicarles un método (una decodificación, una regla del recorrido del código).
